A — Multi-circle row (aggregated flows)

Two (or three) full battery circles in the bottom slot. Each shows its own SoC and in/out. Flow lines still attach to the battery group; distribution uses the sum.

  • Backward compatible: single object still works
  • Editor: sortable battery list
  • Best match for #133 “see packs independently”
# entities.battery as array (or single object)
battery:
  - name: House
    entity:
      consumption: sensor.house_batt_out
      production: sensor.house_batt_in
    state_of_charge: sensor.house_soc
  - name: EcoFlow
    entity: sensor.ecoflow_power
    state_of_charge: sensor.ecoflow_soc
    invert_state: true

B — Three packs, slightly denser circles

Same config model as A, at the max of three. Circles shrink a few pixels so labels and dual-state values still fit on a phone-width card.

  • Hard cap at 3 keeps the classic topology readable
  • Same aggregation rules as A
  • Names become the main way to tell packs apart
battery:
  - name: Powerwall
    entity: sensor.pw_power
    state_of_charge: sensor.pw_soc
  - name: Anker X1
    entity:
      consumption: sensor.x1_discharge
      production: sensor.x1_charge
    state_of_charge: sensor.x1_soc
  - name: Solix E10
    entity: sensor.e10_power

C — One tile, many entities

Keep the classic single battery circle. Pipe-sum charge/discharge entities (already partly supported for power strings) plus a combined SoC mode: min–max range and/or capacity-weighted average.

  • Smallest UI change; solves “stop forcing helpers”
  • Does not show packs independently
  • Needs capacity metadata for a meaningful combined %
battery:
  entity:
    production: sensor.a_charge|sensor.b_charge
    consumption: sensor.a_discharge|sensor.b_discharge
  state_of_charge:
    mode: min_max   # or: weighted | average
    entities:
      - entity: sensor.a_soc
        capacity: 13.5
      - entity: sensor.b_soc
        capacity: 5

D — Primary in graph + satellite packs

Keep one battery in the classic graph position for flow lines. Extra packs hang below as smaller satellites — useful for plug-in stations (#276) that should not rewrite solar↔grid math, or for “display_only” packs.

  • Clear hierarchy: main storage vs secondary packs
  • Needs a role / flow flag in config
  • Taller card; more layout complexity than A
battery:
  - name: Main
    role: primary          # participates in distribution
    entity: sensor.main_batt
    state_of_charge: sensor.main_soc
  - name: Plug-in
    role: satellite        # display / home-attached
    entity: sensor.plug_batt
    state_of_charge: sensor.plug_soc
  - name: Garage
    role: satellite
    entity:
      consumption: sensor.garage_out
      production: sensor.garage_in
    state_of_charge: sensor.garage_soc

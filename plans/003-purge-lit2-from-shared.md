## Why this matters

The monorepo standardizes on Lit 3 (`lit: ^3.3.2`), but `packages/shared` also declares `lit-element: ^2.5.1` and `lit-html: ^2.8.0` as dependencies, and three editor components import decorators from `lit-element`. Cards are bundled with rollup + `nodeResolve`, so **two major versions of Lit land in every published card bundle** — wasted bytes shipped to every Home Assistant user, plus a cross-major interop risk (Lit 2 `lit-element` drags its own `lit-html` 1.x line internally). The fix is three one-line import changes and deleting two dependencies.

## Current state

- The three offending imports (each file already imports core APIs from `lit` on a neighboring line — only the decorator import is wrong):
  - `packages/shared/src/ui-editor/components/individual-devices-editor.ts:11` — `import { property, state } from "lit-element";` (line 10 right above it: `import { css, type CSSResultGroup, html, LitElement, type TemplateResult } from "lit";`)
  - `packages/shared/src/ui-editor/components/link-subpage.ts:4` — `import { property, query } from "lit-element";`
  - `packages/shared/src/ui-editor/components/subpage-header.ts:6` — `import { property } from "lit-element";`
- The Lit-3 convention used everywhere else in the repo (exemplar: `packages/flixlix-cards/power-flow-card-plus/src/ui-editor/ui-editor.ts:19`):

```ts
import { customElement, property, state } from "lit/decorators.js";
```

- `packages/shared/package.json` `dependencies` block contains:

```json
"lit-element": "catalog:packages",
"lit-html": "catalog:packages",
```

  (`lit` itself is correctly a peerDependency: `"lit": "catalog:packages"`.)
- `pnpm-workspace.yaml` `catalogs.packages` contains `lit-element: ^2.5.1` and `lit-html: ^2.8.0`.
- No source file imports from `lit-html` at all (verified: `grep -rn 'from "lit-element"\|from "lit-html"' packages apps --include="*.ts" | grep -v node_modules` returns only the three lines above).
